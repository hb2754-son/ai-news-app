뉴스 수집기 앱의 새 기능 개발 워크플로우를 아래 순서대로 실행한다. 각 단계가 끝나기 전에는 다음 단계로 넘어가지 않는다.

## 1단계. 현재 상태 확인

1. `git status`와 `git branch --show-current`로 현재 브랜치와 작업 트리 상태를 확인한다.
2. 현재 브랜치가 `main`이 아니면:
   - 현재 브랜치 이름을 알리며 **경고**한다.
   - 커밋되지 않은 변경 사항이 있으면 함께 알린다 (임의로 버리거나 stash하지 않는다).
   - "main으로 이동할까요?"라고 묻고 사용자의 답을 기다린다. 승인하면 `git checkout main`, 거절하면 워크플로우를 중단한다.
3. `main`인데 커밋되지 않은 변경 사항이 있으면 알리고 어떻게 할지 묻는다.

## 2단계. 새 브랜치 생성

- 브랜치 이름: `$ARGUMENTS`
- `$ARGUMENTS`가 비어 있으면:
  1. 어떤 기능을 개발할 것인지 사용자에게 묻는다.
  2. 답변을 바탕으로 **영어 소문자-하이픈 형식**(예: `category-edit-delete`)의 이름을 제안하고 확인을 받는다.
- 입력받은 이름이 영어 소문자-하이픈 형식이 아니면 변환안을 제안한다.
- 같은 이름의 브랜치가 이미 있으면 알리고 다른 이름을 받는다.
- 확정되면 `git checkout -b <브랜치-이름>`으로 생성한다.

## 3단계. 개발 시작 안내

브랜치 생성이 끝나면 **"이제 개발을 시작하세요!"** 라고 안내한다. 이어서 `CLAUDE.md`를 읽고 아래 내용을 다시 알려준다.

- 기술 스택: Next.js App Router(16.x) · React 19 · TypeScript · Tailwind CSS 4 · Clerk · Neon Postgres · Drizzle ORM · Claude API · Notion MCP
- 컨벤션:
  - 외부 서비스(RSS, Claude, Notion)는 `src/lib/` 아래에서 서비스별로 분리한다.
  - DB 쿼리는 `src/db/queries/`로 분리해 API 라우트를 얇게 유지한다.
  - 별칭 `@/*` → `src/*`를 사용한다.
  - UI 작업 전에는 `ui.md`를 먼저 읽고 따른다.
  - Next.js 코드 작성 전에는 `node_modules/next/dist/docs/`의 관련 가이드를 먼저 읽는다.
  - PRD §8의 미정 사항은 임의로 정하지 말고 사용자에게 확인한다.
- 명령어: `npm run dev`, `npm run build`, `npm run lint`

그 후 사용자가 개발 요청을 하면 평소처럼 작업을 도와준다. 개발이 끝나면 **'완료'** 또는 **'done'**을 입력하라고 안내한다.

## 4단계. 완료 처리 (사용자가 '완료' 또는 'done'을 입력했을 때)

1. `git status`와 `git diff --stat`으로 **변경된 파일 목록**(추가/수정/삭제 구분)을 보여준다.
2. 변경 내용을 `git diff`로 살펴보고, 저장소의 기존 커밋 메시지 스타일(`git log --oneline`, 한국어)에 맞춰 **커밋 메시지를 자동으로 제안**한다.
3. 필요하면 `npm run lint`를 먼저 실행해 결과를 알린다. 실패하면 사용자에게 알리고 진행 여부를 묻는다.
4. 사용자가 확인(또는 메시지 수정)하면:
   - `.env.local` 등 비밀 정보 파일이 포함되지 않았는지 확인한 뒤 변경 파일을 `git add`한다.
   - 커밋한다. 커밋 메시지 끝에 시스템이 지정한 `Co-Authored-By` 줄을 붙인다.
   - `git checkout main` 후 `git merge --no-ff <브랜치-이름>`으로 병합한다.
   - 충돌이 나면 임의로 해결하지 말고 충돌 파일을 보여주며 사용자와 상의한다.
5. `git push`는 사용자가 요청하기 전에는 하지 않는다. 병합한 브랜치를 삭제할지는 묻는다.

## 5단계. 작업 요약

병합이 끝나면 다음을 요약해서 보여준다.

- 브랜치 이름과 병합 커밋 해시
- 개발한 기능 요약 (무엇을 왜 바꿨는지)
- 변경된 파일 목록
- 다음에 할 일 제안 (예: push, 미구현 기능, CLAUDE.md 갱신 필요 여부)
